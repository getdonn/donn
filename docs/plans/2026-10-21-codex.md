# Codex Adapter Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `zzpersona codex` launches Codex with the persona's instructions, MCP servers and
secrets, sandbox defaults, and an honest loss report.

**Architecture:** A `gh stack` on `feature/codex-0-spec`, one layer per task
(`gh stack add feature/codex-<n>-<name>`). A pure adapter builds `codex` launch arguments as TOML
`-c` overrides; the CLI's shared launch path (extracted from `claude`) runs it.

**Tech Stack:** TypeScript, pnpm, turborepo, vitest; Codex CLI 0.163.0 for the opt-in e2e.

**Spec:** `docs/planning/12-codex.md`

## Global Constraints

- Defaults, verbatim: `-s workspace-write`, `-a on-request`. Overrides: `targets.codex.sandbox`
  (`read-only | workspace-write | danger-full-access`), `targets.codex.approval`
  (`on-request | never`), `targets.codex.model`.
- Instructions only through `-c developer_instructions=…`; never `model_instructions_file`.
- Never pass `--dangerously-bypass-hook-trust` or `--dangerously-bypass-approvals-and-sandbox`.
- Every `-c` value is TOML: basic strings escape `\\`, `"`, `\n`, `\r`, `\t` and other control
  characters as `\uXXXX`; inline tables `{k = v, …}` with keys sorted.
- Reasons, verbatim: skills `Codex has no per-launch skill root`; hooks `untrusted hooks do not run, and zzpersona never bypasses Codex's hook trust`;
  shared variable `another MCP server already uses <VAR> for a different secret; Codex forwards variables by name`;
  looser default `looser than zzpersona's default`.
- Secret values only ever reach the launch environment (never args, files, logs, `--json`).
- Every layer passes `pnpm turbo run build check-types lint test` and `pnpm format:check`;
  commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A secret inside a stdio server's `args`, or in a URL server's `headers`, cannot be forwarded by
   name: the server is dropped with a reason, never launched with a literal `secret://` arg →
   Task 1 test "drops a server whose secret cannot be forwarded".
2. Instructions containing `"""`, backslashes, tabs and emoji round-trip exactly through TOML →
   Task 1 test "encodes instructions as a TOML string Codex reads back".
3. An MCP server name with characters TOML bare keys refuse (a dot, a space) is quoted, not split
   into nested keys → Task 1 test "quotes server names that are not bare keys".
4. `zzpersona codex -- --help` passes `--help` to Codex after all zzpersona's own arguments →
   Task 3 test "passes passthrough arguments last".
5. A persona whose only change from a Claude Code persona is `targets.claude-code` produces no
   Codex report entry for it (not Codex's loss) → Task 1 test "ignores other harnesses' targets".

### Task 1: The adapter (`feature/codex-1-adapter`)

**Files:** Create `src/packages/adapters/codex/` mirroring `adapters/agents-md` (package
`@zzpersona/adapter-codex`): `src/index.ts`, `capabilities.ts`, `compile.ts`, `activate.ts`,
`detect.ts`, `toml.ts`, tests `compile.test.ts`, `activate.test.ts`, `toml.test.ts`,
`detect.test.ts`, `conformance.test.ts`, `golden.test.ts`, `test/golden/`.

**Interfaces:**
- `toml.ts`: `tomlString(value: string): string`, `tomlKey(key: string): string` (bare when
  `/^[A-Za-z0-9_-]+$/`, else a quoted string), `tomlValue(value: string | string[] | Record<string, string>): string`.
- `compile` → `files: { "instructions.md": { content } , "launch.json": { content: JSON of { servers: Record<name, { command?, args?, env?, env_vars?, url? }>, approvals: [server, tool][] } } }`,
  `secretEnv: Record<VAR, ref>`, report. Instructions text: `## zzpersona persona: <id>` header line
  as the Claude Code adapter, instructions, knowledge, then `## Tool rules` exactly as
  `agents-md` renders it.
- `activate({ output, ir, passthrough, cwd })` → one launch step
  `{ command: "codex", args: ["-s", sandbox, "-a", approval, "-c", "developer_instructions=" + tomlString(text), …servers, …approvals, ...(model ? ["-m", model] : []), ...passthrough], env: {} }`
  with servers as `-c mcp_servers.<tomlKey(name)>=<inline table>` and approvals as
  `-c mcp_servers.<tomlKey(server)>.tools.<tomlKey(tool)>.approval_mode="approve"`.
- Capabilities per spec §1 table (permissions `approximated` with note `MCP tool allow rules are exact`).
