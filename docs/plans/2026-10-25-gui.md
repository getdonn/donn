# The GUI (spec 26, layers 1–3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `donn ui` opens a local web app, served by the daemon over a loopback bridge, that
shows and does what the CLI does (personas and layers with explain, sessions and switching,
capabilities, the registry, agents and the agent builder), with no logic of its own.

**Architecture:** A `gh stack` on `develop`. Layer 0 `feature/spec-26-plan` (dated amendments to
spec 26, this plan). Layer 1 `feature/gui-1-bridge` (Tasks 1–5: output schemas, the bridge in the
daemon, jobs/events/open, env secrets for daemon runs, `donn ui`). Layer 2 `feature/gui-2-app`
(Tasks 6–9: `src/apps/ui` and screens 1–4). Layer 3 `feature/gui-3-agents` (Tasks 10–13:
`donn agent add` + the question protocol, `donn agent templates`, the agents screens and the
builder, the end-to-end suite, docs). The desktop shell (spec 26 layer 4) is deferred.

**Tech Stack:** Node 26 / TypeScript 7, zod 4, vitest; the app: Vite 8, React 19, Tailwind CSS
v4 (`@tailwindcss/vite`), shadcn/ui (components copied into the app, the `shadcn` CLI 4 at
setup), react-router 8, TanStack Query 5, Playwright 1.64 for the end-to-end suite.

**Spec:** `docs/planning/26-gui.md` (amended 2026-10-25), with `25` §6 (the question protocol,
moved to 26), `14`–`16` (the daemon), `15` (`POST /run`), `17` (switch report), `13`
(capabilities), `18`–`20` (registry, identity).

## Global Constraints

- The GUI holds no logic: every read and action is a CLI operation through the bridge, so
  `donn … --json` can do the same. The app never reads files, the socket or the network directly.
- The bridge listens on `127.0.0.1` only, a random free port, while a UI session is open; idle
  close after 10 minutes without a session; `daemon: { ui: false }` in `~/.donn/config.yaml`
  disables it. Auth: `Authorization: Bearer <ui token>` on every `/v1` request; the UI token is
  separate from the socket token and rotated each time the bridge opens; never cookies.
- `Host` must be `127.0.0.1:<port>` or `localhost:<port>`; a present `Origin` must equal
  `http://<that host>`; otherwise `403`. The one-time code works once, within 60 s.
- The UI allowlist (every form with `--json`): `list`, `switch` (the forms `/run` allows),
  `resolve` (incl. `--explain`), `compile` (for the compile reports; ruling 2026-10-25),
  `capabilities`, `diff`, `status`, `doctor`, `whoami`, `login`,
  `logout`, `pull`, `publish`, `write`, `managed build|check`, every `agent` subcommand except
  `exec` and `logs --follow`. Never `daemon`, `mod`, `managed install|uninstall`, `migrate`,
  `init`, `live`, `claude`, `codex`. `/run`'s own allowlist is unchanged.
- Outward actions (`publish`, `agent deploy`) run only after a dialog showing what the CLI would
  prompt (publish: its `--dry-run` result; deploy: the env names); the CLI is unchanged.
- Secret values never reach the app, a log, an event or JSON other than `agent env --resolve`
  (which the UI never calls with `--resolve`).
- Every new CLI command supports `--json`. Errors are `CliError(code, message, details)`.
- `@getdonn/cli-schemas` is a private workspace package (`"private": true`), a devDependency of
  `@getdonn/cli` and a dependency of `src/apps/ui` (which is private too). The app's production
  build is copied into `src/apps/cli/dist/ui/` by the CLI's build; `@getdonn/cli`'s `files`
  already ships `dist`.
- Tests never touch the real home, keychain, network, Docker or a real registry (seed() homes,
  fake eve, the mock registry from `@getdonn/registry-api`). Playwright runs headless Chromium
  only, against `donn ui --no-open` with a temp home.
- Every layer passes `pnpm turbo run build check-types lint test` and `pnpm format:check`.
  Commits: `git commit -s`, ending with `Co-Authored-By: Claude Opus 5.5
  <noreply@anthropic.com>` and `Claude-Session:
  https://claude.ai/code/session_01GmLJYkbT5dYe37adTR8fab`. Changesets per layer.

## Review Focus

1. A page from another origin (`Origin: https://evil.example`) or a DNS-rebound host (`Host:
   evil.example:<port>`) sends `POST /v1/run` with a guessed or stolen token → `403` before any
   CLI code runs → Task 2 tests.
2. `argv` smuggling: `["agent","exec","x","--","rm"]`, `["daemon","stop"]`, `["switch","--json",
   "--project","/"]` with a flag `/run` refuses, a missing `--json` → `403` naming the rule →
   Task 2.
3. `POST /v1/open` with `../` paths, a symlink out of a personas root, or an absolute path
   outside known roots → refused, nothing spawned → Task 3.
4. A secret value for a persona ref appears nowhere in the bridge's responses, events, the
   daemon log or the app's DOM after `agent run` / `agent build` / `agent env` (without
   `--resolve`) → Tasks 4, 11, 13.
5. The bridge closes after 10 idle minutes (injected clock), and a stale tab then gets a clear
   "session ended, run donn ui" state, not a hang → Tasks 2, 6.

### Task 2: The bridge (same branch)

**Files:** Create `src/apps/cli/src/daemon/bridge.ts`, `daemon/ui-allow.ts`; modify
`daemon/server.ts` (socket route `POST /ui/open`, close the bridge on daemon close), `config.ts`
(`daemon.ui?: boolean`); tests `daemon-bridge.test.ts`.

**Interfaces (produces):**
- `openBridge(options: { home; io; runInProcess; now?; idleMs? = 600_000; port? }):
  Promise<Bridge>`; `Bridge { port; code(): string /* new one-time code, 60 s */; close();
  closed: Promise<void> }`. `POST /ui/open {port?}` on the socket returns `{ port, code }`
  (opening the bridge if needed; `403 ui-disabled` when `daemon.ui` is false).
- `POST /v1/session { code }` → `{ token }` (the UI token; code consumed); bad/used/expired code
  → `401`.
- `uiAllowed(argv: readonly string[]): { ok: true } | { ok: false; rule: string }` per Global
  Constraints; `POST /v1/run { argv, cwd }` → `{ exitCode, stdout, stderr }` via the same
  `runInProcess` as `/run`; refused → `403 { error: { code: "not-allowed", message, rule } }`.
- `cwd` check: a project the daemon knows (a session's or a created agent's) or one in
  `~/.donn/ui.json` (`{ projects: string[] }`); else `403 unknown-project`.
- Static: `GET /` and assets from `<cli dist>/ui/` (resolved from the module URL), SPA fallback
  to `index.html` for non-`/v1` GET paths, `Cache-Control: no-store` for `index.html`;
  `Content-Security-Policy: default-src 'self'; connect-src 'self'; img-src 'self' data:;
  style-src 'self' 'unsafe-inline'` on every response. When `dist/ui` is absent (dev), `GET /`
  answers `503 ui-not-built`.
- Host/Origin check before auth; token check before routing; idle timer reset by any `/v1`
  request or open SSE stream.

### Task 3: Jobs, events and open (same branch)

**Files:** Modify `daemon/bridge.ts`; create `daemon/jobs.ts`; tests in `daemon-bridge.test.ts`.

**Interfaces (produces):**
- `POST /v1/jobs { argv, cwd }` → `{ id }`; the job runs `runInProcess` with stdout/stderr line
  callbacks; events `job.progress { id, line }` (stderr lines; a job never resolves secret
  values except `agent run`'s, whose lines the spec 25 runner already redacts), `job.question { id, question, continue }` (Task 10 fills it),
  `job.done { id, exitCode, stdout }`; `GET /v1/jobs/<id>` → state and result.
  `runInProcess` gains an optional `{ onStdout?, onStderr? }` (the existing callers unchanged).
- `GET /v1/events` → SSE: every daemon event (spec 14, the `agent.*` events) plus `job.*`;
  heartbeats every 15 s (`: ping`).
- `POST /v1/jobs/<id>/answer { key, value }` → re-runs the job's `continue` argv with `--answer
  key=<JSON>` appended (Task 10 defines `continue`), as a new job linked to the first.
- `POST /v1/open { path }` → spawns `$VISUAL`, `$EDITOR` (split on spaces) or the OS opener
  (`open` / `xdg-open`) with the path, detached; the path, realpath'd, must be inside the
  personas root (config), `<home>/personas`, a known project (as `cwd`) or a created agent dir;
  else `403 outside-roots`. `POST /v1/projects { path }` adds a project to `ui.json` after
  checking it has `.donn/persona.yaml`.
- Jobs are kept 1 hour after done, at most 100.

- [ ] **Step 1: Failing tests:** a job streams progress then done; the SSE stream carries a daemon
  event and a job event; Review Focus 3 (`../`, symlink, absolute outside) and a good path
  spawns the fake opener with the path; projects added only with a persona.

### Task 4: Env secrets for daemon runs (same branch)

**Interfaces (produces):** `POST /agents/run { project, name, env?: Record<ref, value> }`: the

sync reuse the values the run was started with.
