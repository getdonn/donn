# Daemon (First Slice) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `zzpersona daemon start` runs a local daemon that refreshes every running Claude Code
session when its persona files change, and `zzpersona status` shows each session's state.

**Architecture:** A `gh stack` on `feature/daemon-0-spec`, one layer per task
(`gh stack add feature/daemon-<n>-<name>`). Session folders (spec 10) stay the registry; the
daemon (`zzpersona daemon run`, in the CLI package under `src/apps/cli/src/daemon/`) serves
HTTP over a unix socket, watches persona sources, and applies the extracted `applyLive` swap.

**Tech Stack:** TypeScript, Node 26 (`node:http`, `fs.watch` recursive), vitest. No new
dependencies.

**Spec:** `docs/planning/14-daemon.md`

## Global Constraints

- Daemon files under `<home>/daemon/` (dir 0700): `sock` (0600), `token` (0600, random 32 bytes
  hex, new each start), `pid`, `daemon.lock`, `daemon.log` (rotate at 1 MiB to `daemon.log.1`),
  `where` (only when the socket is elsewhere).
- Socket fallback when `Buffer.byteLength(<home>/daemon/sock) > 103`: `<os.tmpdir()>/zzpd-<8 hex
  of sha256(home)>.sock`.
- Debounce 300 ms (injectable for tests).
- States, verbatim: `current`, `refreshed`, `stale`, `refresh-failed`.
- Events, verbatim: `session.added`, `session.ended`, `session.refreshed`, `session.stale`,
  `session.refresh-failed`, `daemon.stopping`.
- Errors: `{ error: { code, message } }`; `401 unauthorized`, `404 not-found`.
- Copy, verbatim: `daemon not running: sessions are not refreshed on edits; zzpersona daemon
  start`; `daemon runs <x>, CLI is <y>; zzpersona daemon stop && zzpersona daemon start`;
  `already running`.
- The daemon never resolves secrets; logs and events carry refs and paths only.
- Every layer passes `pnpm turbo run build check-types lint test` and `pnpm format:check`;
  commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Tests use a
  temporary home; never the user's `~/.zzpersona` or `~/.claude`.

## Review Focus

1. A session whose project folder was deleted (or moved) while it runs: refresh reports
   `refresh-failed` for that session only; others still refresh → Task 3 test "isolates a
   session whose project is gone".
2. An edit landing while a swap is in flight: the second refresh waits for the first (no
   interleaved plugin folders), and the final state reflects the last edit → Task 3 test
   "serialises refreshes and applies the last edit".
3. A `daemon start` while a daemon from a *different* home runs: both run, each with its own
   socket and token (no global singleton) → Task 2 test "runs one daemon per home".
4. `zzpersona status` against a daemon that died without cleanup (stale `sock`/`pid`): falls back
   to in-process listing with the not-running note, never hangs → Task 4 test "falls back when
   the socket is dead".
5. A request with a token from a previous daemon run: 401, and the CLI client re-reads the token
   file once before failing → Task 4 test "re-reads a rotated token".

### Task 2: The daemon process (`feature/daemon-2-daemon`)

**Files:** Create `src/apps/cli/src/daemon/{paths.ts,server.ts,client.ts,log.ts}`,
`src/apps/cli/src/commands/daemon.ts`, `src/apps/cli/src/daemon.test.ts`. Modify `cli.ts`
(register `daemon run|start|stop|status`), `CliIo` (optional `spawnDaemon`).

**Interfaces (produces):**
```ts
// daemon/paths.ts
function daemonPaths(home: string): { dir; sock; token; pid; lock; log; where };
// daemon/server.ts
interface DaemonOptions { home: string; env: NodeJS.ProcessEnv; version: string; debounceMs?: number; now?: () => number }
interface Daemon { socket: string; token: string; startedAt: string; refresh(): Promise<void>; close(): Promise<void> }
function startDaemon(options: DaemonOptions): Promise<Daemon>; // throws CliError("daemon-running", "already running") if the lock is held by a live pid
// daemon/client.ts
interface DaemonClient { status(): Promise<DaemonStatus>; refresh(): Promise<void>; shutdown(): Promise<void>; events(on: (e: DaemonEvent) => void): () => void }
function connectDaemon(home: string): Promise<DaemonClient | undefined>; // undefined when no socket answers within 500 ms
interface DaemonStatus { version: string; pid: number; startedAt: string; watching: string[]; sessions: SessionStatus[] }
interface SessionStatus { dir; harness; project?; launched: string; live?: string; startedAt?; held: string[]; state: "current" | "refreshed" | "stale" | "refresh-failed"; at?: string; error?: string }
// CliIo
spawnDaemon?: (home: string) => Promise<void>; // default: spawn process.execPath [bin, "daemon", "run"] detached, stdio to daemon.log
```
This task serves `GET /status` (sessions from `listSessions`, state `current` for all) and
`POST /shutdown`; Task 3 adds events, refresh and watching.

### Task 3: Watch and refresh (`feature/daemon-3-watch`)

**Files:** Create `src/apps/cli/src/daemon/{watch.ts,refresh.ts}`, `src/apps/cli/src/daemon-watch.test.ts`. Modify `daemon/server.ts`.

**Interfaces (produces):**
```ts
// daemon/refresh.ts
function refreshSession(io: CliIo, session: SessionInfo): Promise<{ state: SessionStatus["state"]; held: string[]; error?: string }>;
// Claude Code: context with cwd = session.launched.project ?? home; persona = live ?? launched;
// overlay = launched.overlay ?? true; prepareBuild; buildHash vs live.buildHash ?? launched.buildHash;
// equal → "current"; else applyLive → "refreshed", or "stale" when held grew; throw → "refresh-failed".
// Codex: compile only; hash differs from launched.buildHash → "stale".
// daemon/watch.ts
function watchSources(paths: string[], onChange: () => void, debounceMs: number): { close(): void; paths: string[] };
```
Watched: `config.personas`, the store's user-layer directory, each running session's
`<project>/.zzpersona`, `<home>/overrides.yaml` and `<home>/config.yaml` (via a non-recursive
watch of `<home>` filtered by name), and `<home>/sessions` (added/ended). The path set is
recomputed after each sessions change. Refreshes run one at a time (a queue of depth one: an edit
during a refresh schedules exactly one more). Dead sessions are removed and emit `session.ended`.
