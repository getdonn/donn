# CLI Reach Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Third-party adapters and secret providers load from config, a built-in OS `keychain`
provider resolves secrets, `zzpersona diff` compares two personas, and the deferred minors that
matter are fixed.

**Architecture:** A `gh stack` on `feature/reach-0-spec` (this plan and the spec are layer 0).
Each task below is one layer, created with `gh stack add feature/reach-<n>-<name>` from the
layer beneath it, and must pass `pnpm turbo run build check-types lint test` on its own. SDK and
adapter fixes come first so the plugin layer can prove them with a class-based fixture adapter.

**Tech Stack:** TypeScript, pnpm, turborepo, zod 4, vitest, commander 15, Node 26 (floor 24).

**Spec:** `docs/planning/08-cli-reach.md`

## Global Constraints

- Secret values only ever reach a launch step's environment: never a file, a log, an error, a
  failure reason or `--json` output.
- Every CLI command supports `--json`; every error envelope is `{"error":{"code","message",...}}`.
- Only listed plugins are imported; nothing scans `node_modules`.
- Plugin package folder: `<home>/adapters/` (shared by `adapters:` and `secretProviders:`).
  Install hint, verbatim: `npm install --prefix <home>/adapters <name>`.
- Built-in adapter ids: `claude-code`. Built-in provider types: `env`, `keychain`.
- `SECRET_PROVIDER_API_VERSION = 1`; `ADAPTER_API_VERSION` stays `1`.
- Public types of `@zzpersona/adapter-sdk` and `@zzpersona/secrets` must not reference the
  `NodeJS` namespace.
- Prettier at width 80 (`pnpm format`); `pnpm format:check` passes on every layer.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. An ESM-only plugin package (`"type": "module"`, `exports: { ".": { "import": "./index.js" } }`)
   must load by name; `require.resolve` would miss it. → Task 4 test "loads an ESM-only package
   by name".
2. A provider whose `resolve` throws, or returns a non-string, must become a failure for that
   ref with the error's message only — no stack, no value. → Task 3 test "a throwing or
   non-string provider is a failure, not a crash".
3. A keychain value ending in spaces or several newlines must lose exactly one trailing `\n`.
   → Task 3 test "strips exactly one trailing newline".
4. A relative plugin entry (`./x`) resolves against the folder of `config.yaml` (the home), not
   the current directory. → Task 4 test "resolves a relative entry against the home, not cwd".
5. `diff` on a keyed entry present on both sides with a different body (an instruction's text)
   is one `changed` row printing `(changed)`, and secret refs print as refs. → Task 5 test
   "a changed instruction is one row and secret refs stay refs".
