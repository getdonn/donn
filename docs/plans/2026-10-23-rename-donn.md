# Rename to donn Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The open-source repo says donn everywhere outside dated history, and `donn migrate` moves an
existing zzpersona install over; released as 0.13.0.

**Architecture:** A `gh stack` on `feature/donn-0-spec` (`gh stack add feature/donn-<n>-<name>`). Task 1
writes and runs a one-off rename script (deleted in the same layer); Task 2 adds `donn migrate`, whose
legacy names live in one file the leftover check exempts; Task 3 is docs and changesets.

**Tech Stack:** TypeScript, Node 26, pnpm, turbo, vitest, changesets. No new dependencies.

**Spec:** `docs/planning/22-rename-donn.md`

## Global Constraints

- The mapping and the replacement order are spec 22 §1–§2, verbatim. The CLI package is
  `@getdonn/cli`, its command `donn`; all packages stay `"private": true`.
- Untouched by the rename: `**/CHANGELOG.md`; `docs/plans/**`; `spikes/**`;
  `docs/planning/22-rename-donn.md`; in `docs/planning/*.md`, any section whose heading contains
  "Amendments" (to the next heading of the same or higher level) and any paragraph starting
  `*Amended` or `*Answered`; `docs/planning/00-handoff.md`'s `## Naming` section; git history.
  Every other `docs/planning/*.md` gains one line after its status block:
  `> 2026-10-23: renamed zzpersona/hatrack → donn (spec 22).`
- `persona-ai` is renamed only where it names the repo (CLAUDE.md title, README), by hand in Task 3 —
  never in paths such as `~/Repos/persona-ai`.
- After Task 2, the only files allowed to contain `zzpersona`, `ZZPERSONA`, `zzp_`, `zzp-`, `ZZP_`,
  `zzpd` or `hatrack` outside the untouched set are `src/apps/cli/src/migrate/legacy.ts` and
  `src/apps/cli/src/migrate.test.ts`.
- `donn migrate` copy: plan header `migrate ~/.zzpersona to <target>:`; refusal when the target
  exists and is not empty: `<target> already exists and is not empty; move it aside or set DONN_HOME`;
  nothing to do: `nothing to migrate: no zzpersona install found`.
- Every layer passes `pnpm turbo run build check-types lint test` and `pnpm format:check`; commits end
  with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and
  `Claude-Session: https://claude.ai/code/session_01KtnoumVTbTBed2oTps5DEp`. Tests never touch the
  real `~/.zzpersona`, `~/.donn`, `~/.claude`, keychain, LaunchAgents, systemd or system folders.

## Review Focus

1. A golden, fixture or corpus whose expected bytes embed a digest or a renamed string (bundle
   digests now hash `donn-bundle/1`; plugin folder names; service files) → regenerated by the tools,
   never hand-edited, and the pipeline green → Task 1 Step 4.
2. Length-sensitive formats after `zzp_` → `donn_` (token shape regexes, bootstrap/session token
   minimum lengths, plugin-name limits) → a freshly issued token matches the new shape and an old
   `zzp_` token is refused → Task 1 test "tokens use the donn_ prefix".
3. `~/.donn` already exists because `donn` ran once before `migrate` → refused with the exact copy,
   nothing moved; with `--yes` too → Task 2 test "an existing non-empty target is refused".
4. A persona file whose `apiVersion` line is quoted (`"zzpersona/v0"`) or followed by a comment →
   only that value changes, the comment and every other byte stay → Task 2 test "apiVersion is
   rewritten in place".
5. An `AGENTS.md` whose generated block body mentions "zzpersona" in persona text → only the two
   marker lines change; `donn write` afterwards replaces the block instead of adding a second one →
   Task 2 test "project markers are rewritten, the block is found again".

### Task 1: The rename (`feature/donn-1-rename`)

**Files:** Create then delete `scripts/rename-donn.mjs`; every tracked file the mapping touches; path
renames via `git mv`.

**Interfaces (produces):** the renamed tree — `@getdonn/*` packages, the `donn` bin in
`src/apps/cli/package.json` (`"bin": { "donn": … }`, package name `@getdonn/cli`), `DONN_*` env,
`dev.getdonn.daemon` / `donn-daemon.service`, `donn-registry`, `donn_` tokens, `donn-bundle/1`,
`50-donn.json` / `donn/`, `X-Donn-*`, `dev.getdonn.managed.<layer>`, `<!-- donn:begin` markers.

- [ ] **Step 1: Write the script** (`node scripts/rename-donn.mjs [--check]`): path pass then text pass
  in spec order; the untouched set from Global Constraints; prints, separately, every changed line that
  contains a regex literal, `RegExp(`, `.length` or a `{n}` quantifier near a renamed token, for hand
  review; `--check` lists leftovers (`zzpersona|zzp[-_d]|ZZP_|ZZPERSONA|hatrack`, case-insensitive)
  outside the untouched set and exits 1 if any. Inserts the dated line in each other planning doc.
- [ ] **Step 2: Run it**, then `pnpm install` (lockfile follows the new package names) and review every
  printed length-sensitive line by hand; fix any regex or length that the new prefix breaks (e.g. a
  48-hex token shape stays 48 hex after `donn_`; minimum lengths that counted the prefix).
- [ ] **Step 3: Failing test** `it("tokens use the donn_ prefix")` (registry mock and CLI token
  handling: a new session/service token starts `donn_` and matches the shape regex; a `zzp_` token is
  refused as unknown).
- [ ] **Step 4: Regenerate expected outputs**: `pnpm turbo run test -- -u` for `toMatchFileSnapshot`
  goldens (adapters, managed, OpenAPI), `pnpm --filter @getdonn/adapter-sdk corpus:update`, and the
  resolver fixtures' expected files (read `fixtures.test.ts` for how they are compared and update the
  `expected`/`explain.txt` files the rename changed); spot-check a sample of each in the diff.
- [ ] **Step 5: Run** the pipeline, `node scripts/rename-donn.mjs --check` (exit 0), then the opt-in
  `DONN_E2E=1` (real Claude Code) and `DONN_E2E_MANAGED=1` (Docker). Do **not** run
  `DONN_E2E_SERVICE` (it installs a real login item; the controller asks the user first).
- [ ] **Step 6: Delete the script and commit** `refactor: rename zzpersona to donn` (the script's
  creation and deletion may be one commit with the rename).
