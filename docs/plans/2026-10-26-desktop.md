# The desktop app (spec 28) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A menu-bar app, built from source, that shows and drives donn through the installed
`donn` CLI: the default persona, live sessions, agents, a switcher, run/stop, and "Open donn" for
the web app in a window.

**Architecture:** A `gh stack` on `develop`. Layer 0 `feature/spec-28-desktop` (spec 28, this
plan). Layer 1 `feature/desktop-1-cli` (Tasks 1–3: `switched`, `status --watch`, `ui --page` and
the app's `?project=`). Layer 2 `feature/desktop-2-shell` (Tasks 4–9: `src/apps/desktop`, the
Rust side, CI). Layer 3 `feature/desktop-3-package` (Tasks 10–11: autostart, single instance,
icons, docs, smoke).

**Tech Stack:** Node 26 / TypeScript 7, zod 4, vitest, Playwright (layer 1); Rust 1.99.1, Tauri
2.12 (`tauri` 2.12.5 with `tray-icon`; `@tauri-apps/cli` 2.12.4), `serde`/`serde_json`, and the
plugins `tauri-plugin-autostart`, `-single-instance`, `-dialog`, `-opener` at their latest 2.x.

**Spec:** `docs/planning/28-desktop.md`, with `26` §1–2 (shells, the bridge), `14`–`16` (the
daemon, events, service), `07` (switch and `state.json`), `17` (switch report).

## Global Constraints

- The shell has no logic the CLI lacks: every read and action is `donn <args> --json` run with
  `std::process::Command` (never through a shell). No Rust code speaks the daemon's socket or the
  bridge, and the web app gets no Tauri code.
- No capability grants IPC to a remote URL; the webview navigates only within
  `http://127.0.0.1:<port>`; other links open in the default browser.
- `donn status --watch` requires `--json`; lines are compact JSON, one object per line, debounced
  250 ms, never two identical lines in a row; no-daemon check every 5 s; never starts the daemon.
- `donn ui --page <path>`: starts with exactly one `/`, contains no `#`; default `/`.
- Minimum CLI for the shell: `0.14.0` (the `@getdonn/cli` minor that ships layer 1).
- `@getdonn/desktop` is `"private": true`, never published, and outside the default `turbo
  build`/`test` (its `build` and `test` scripts are no-ops).
- macOS and Linux only. Built from source; ad-hoc signed; no CI artifacts, no `release.yml` change.
- Tests never touch the real home, keychain, service managers, network or a real registry; no
  test opens a real browser or a real tray.
- Every layer passes `pnpm turbo run build check-types lint test` and `pnpm format:check`; the
  Rust side passes `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`.
  Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and
  `Claude-Session: https://claude.ai/code/session_01GmLJYkbT5dYe37adTR8fab`. A changeset in layer
  1 (`@getdonn/cli` minor).

## Review Focus

1. Finder-launched app: the login shell prints noise (a motd, `nvm` output) around `command -v
   donn`, or `donn` is a shim script → the shell takes the last line that is an absolute path and
   runs it → Task 6 test `parses_command_v_with_noise`.
2. A burst of daemon events (an agent sync touching ten files) → at most one line per 250 ms and
   no repeat of an unchanged object → Task 2 test "bursts and repeats".
3. The daemon restarts while `--watch` runs → a `daemon: false` line, then a full line after it
   is back, without the child exiting → Task 2 test "follows a restart".
4. The shell quits → its `status --watch` child exits (closed stdout) and leaves no Node process
   → Task 2 test "exits on a closed stdout"; Task 8 kills the child on exit.
5. Two live projects whose folders share a name (`~/a/api`, `~/b/api`) → their tray lines differ
   (`api (a)`, `api (b)`) → Task 7 test `disambiguates_same_named_projects`.

### Task 2: `donn status --watch --json` (same branch)

**Files:** Create `src/apps/cli/src/commands/status-watch.ts`; Modify `src/apps/cli/src/cli.ts`
(`--watch` on `status`); Test `src/apps/cli/src/status-watch.test.ts`.

**Interfaces:**
- Consumes: `statusSnapshot(io)` (Task 1); `connectDaemon(home, …).events(on)` (returns a stop
  function); `io.signal` (stops the watch; defaults to SIGINT/SIGTERM); `io.sleep`.
- Produces: `watchStatus(io: CliIo, options: { debounceMs?: number; pollMs?: number }):
  Promise<number>` with defaults 250 and 5000. A `state.json` change is seen with `fs.watch` on
  the home directory, filtered to `state.json` (atomic writes replace the file).

- [ ] **Step 1: Failing tests** (`zz` with an `AbortController` signal; read lines from stdout;
  short `debounceMs`/`pollMs` through an exported test seam):
  - "requires --json": `status --watch` → the CLI's usage error (code `usage`, as other usage errors exit), message "--watch prints JSON lines; add --json".
  - "prints a first line": daemon up → first line parses with `StatusOutput`, `daemon: true`.
  - "prints after an event": a session added (`session.added`) → a second line with it.
  - "prints after a switch": `zz(["switch","team/payments","--default"])` → a line whose
    `switched.default` is `team/payments`.
  - "bursts and repeats": ten `POST /refresh` calls inside 50 ms → at most two new lines; an event
    that changes nothing → no new line.
  - "no daemon": first line `daemon: false`; start a daemon → a `daemon: true` line within
    `pollMs`; it never starts a daemon itself (`spawnDaemon` stub not called).
  - "follows a restart": close the daemon → a `daemon: false` line; start a new one → a
    `daemon: true` line; the command has not returned.
  - "exits on a closed stdout": a stdout whose `write` throws `EPIPE` → returns 0 and stops
    following (the daemon's `close()` then resolves without waiting on an open stream).
  - "stops on the signal": abort → returns 0.
- [ ] **Step 2:** Run → FAIL.
- [ ] **Step 3:** Implement; compact `JSON.stringify(obj)` per line; compare with the last line's
  text to skip repeats; on `daemon.stopping` or a follow error, print the `daemon: false` object
  and resume polling every `pollMs`.
- [ ] **Step 4:** Tests pass; full CLI suite green.
- [ ] **Step 5:** Commit `feat(cli): status --watch --json streams snapshots`.
