# 11 — The `agents-md` adapter: a committed `AGENTS.md` from the project persona

> Status: design, 2026-10-21. Phase 2, first spec (order agreed: agents-md, Codex, capability
> matrix docs, daemon). Builds on `05-adapter-sdk.md` (overlay steps, conformance kit),
> `06-cli-core-loop.md` (executor) and `spikes/agents-md/FINDINGS.md`. Built as a `gh stack`:
> layer 0 is this spec and its plan.

## Intent

Render the repo's project persona into its `AGENTS.md`, inside a marked block, so every tool that
reads `AGENTS.md` (Codex, Copilot CLI, Gemini CLI when configured, Claude Code without a
`CLAUDE.md`) and every teammate gets the persona's instructions, with or without zzpersona. A CI
check keeps the block current.

Done means: `zzpersona write` puts the project persona into `<repo>/AGENTS.md` without disturbing
anything outside the block; `zzpersona write --check` fails when the block is stale; the report
names everything an `AGENTS.md` cannot carry; and Codex, given the file, follows it.

## Decisions (and the alternatives rejected)

| Decision | Rejected | Why |
|---|---|---|
| A committed file generated from the project persona | Per-user activation that writes the user's persona into the working tree and restores it | Shared and deterministic; no per-user edits to a tracked file; Codex and Copilot get real adapters for personal switching |
| A marked block inside the repo's own `AGENTS.md` | Own the whole file; a separate file | Hand-written repo rules stay; every tool tested concatenates the repo file, so the block must live in it (spike) |
| The adapter stays pure; the executor merges the block | The adapter reads the repo file | Deterministic compile, conformance-testable |
| An optional `block` on the SDK's overlay step | A new step kind | Additive; whole-file overlays keep working |
| `zzpersona write` executes overlay plans; `runPlan` keeps refusing them | Overlays run as part of a launch | Writing tracked files and launching a tool are different operations |

## 1. What is rendered

**Persona:** always `project/persona`, resolved without the user overlay, switches or the default
(a committed file must be the same for every teammate). No project persona: `no-project-persona`
(fix `zzpersona init --extends <persona>`). A project persona whose layers include `user/`:
`user-layer-in-shared-file`.

**Block contents,** in order:

1. `Generated by zzpersona from project/persona (<layers, " → ">); edit the persona, not this block.`
2. Instructions, in resolved order: inline text, file instructions inlined.
3. Knowledge pointers, as the Claude Code adapter renders them (`## Knowledge sources`).
4. Permissions as guidance, when any: `## Tool rules` with `Never run:` (deny), `Ask before:`
   (ask), `Allowed:` (allow), each a list of the rules as written.

**Report:** instructions and knowledge `native`; permissions `approximated` ("rendered as
guidance; not enforced"); skills, `mcp.servers`, `mcp.gateway`, hooks, secrets and `targets.*`
`dropped` with a reason ("AGENTS.md is plain text; use a harness adapter for …"). A warning when
the block exceeds 24 KiB (Codex caps the instructions it reads; the limit is confirmed with the
Codex adapter).

## 2. The block

```markdown
<!-- zzpersona:begin — generated from project/persona; edit the persona, not this block -->
…
<!-- zzpersona:end -->
```

| `<repo>/AGENTS.md` | Result |
|---|---|
| missing | created with only the block |
| no markers | block appended after a blank line |
| one block | text between the markers replaced |
| begin without end, end without begin, or two blocks | `agents-md-markers` naming the line; nothing written |

Text outside the markers is preserved byte for byte, including CRLF line endings (the block is
written with the file's line ending). The block renders deterministically and ends with a newline,
so an unchanged persona produces no diff. Writes are atomic. `--remove` deletes the block and its
markers, and the file when nothing else remains. `<repo>` is the parent of `.zzpersona/`; nested
`AGENTS.md` files are not touched.

In a repo with no `CLAUDE.md`, Claude Code reads `AGENTS.md`, so a `zzpersona claude` session
would get the persona's instructions twice (launch and file); the text is the same. The report
notes it, and `doctor` mentions it when both apply.

## 3. Adapter, SDK, executor, command

- **`@zzpersona/adapter-agents-md`:** `compile` renders the block text and the report;
  `activate` returns `{ steps: [{ kind: "overlay", path: "AGENTS.md", content, block:
  "zzpersona" }] }`. `detect` reports `{ installed: true, version: "n/a" }` (a file format).
- **SDK:** the overlay step gains optional `block?: string`. Without it, `content` is the whole
  file; with it, `content` is the text between `<!-- <block>:begin … -->` and
  `<!-- <block>:end -->`. The conformance kit checks overlay plans (relative path inside the
  project, no `..`). Spec 05 open question 1 gets a dated note.
- **Executor:** `applyOverlay(step, root, { mode: "write" | "check" | "remove" })` →
  `{ path, status: "created" | "updated" | "unchanged" | "removed" | "stale" }`, implementing
  section 2; a `path` outside `root` is refused. `runPlan` still refuses overlay steps.
- **CLI:** `zzpersona write [--harness agents-md] [--check | --remove] [--json]`. `agents-md` is
  the default and the only file harness; another harness is `not-a-file-harness`. Text output
  `<status> AGENTS.md (zzpersona block, <size>)` plus the report's dropped and approximated lines;
  `--json` `{ path, status, report }`. `--check` writes nothing and exits 1 for `stale` or a
  missing block. `compile --harness agents-md` prints the block and the report (a dry run).

## 4. Capabilities and testing

| Field | agents-md |
|---|---|
| instructions, knowledge | native |
| permissions | approximated |
| skills, mcp.servers, mcp.gateway, hooks, secrets, `targets.*` | dropped |

| Layer | Contents |
|---|---|
| 0 `spec` | this spec and its plan |
| 1 `sdk` | `block` on overlay steps; conformance checks for overlay plans |
| 2 `adapter` | `@zzpersona/adapter-agents-md`: compile, activate, capabilities, golden builds, conformance |
| 3 `executor` | `applyOverlay` |
| 4 `cli` | `zzpersona write`, project-persona selection and refusals, `compile --harness agents-md`, doctor's note |
| 5 `e2e-docs` | opt-in e2e with Codex; README, changeset, the spec 05 note, CLAUDE.md |

- **Adapter:** golden builds from the conformance corpus; the kit's checks.
- **Executor:** every row of section 2's table; CRLF; byte-for-byte preservation; malformed
  markers write nothing; escaping paths refused; `remove` deleting an emptied file.
- **CLI:** write then `--check` passes; a persona edit makes `--check` fail; `--remove`; the user
  overlay and switches ignored; the `user/` refusal; no project persona; `--json`.
- **Opt-in e2e (`ZZP_E2E=1`):** write the block into a scratch repo, `codex exec` quotes a
  codeword from it (the spike's probe).

## Non-goals

Per-user activation; nested `AGENTS.md`; `GEMINI.md` and Copilot `.instructions.md` (their own
adapters); Windows.

## Open questions

1. A pre-commit hook for `zzpersona write`; `--check` in CI is enough for now.
2. Codex's real instructions size limit (with the Codex adapter).

## Amendments from implementation (2026-10-21)

Made while building this spec (`docs/plans/2026-10-21-agents-md.md`). Each overrides the section
it names.

- **§4 knowledge** is `advisory` ("listed as pointers in AGENTS.md"), the outcome the Claude Code
  adapter gives the same rendering, not `native`.
- **§1 report** drops only `targets.agents-md` (another harness's `targets` block is not this
  adapter's loss, as the SDK defines it), plus `mcp.gateway` when set.
- **§2 markers:** the executor's begin marker is generic,
  `<!-- <block>:begin — generated; edit the source, not this block -->`; the block's first line
  names the persona.
- **§3 SDK:** the conformance kit gains `noBinary` for adapters of a file format: `detect` must
  report installed and run nothing.
- **§2 remove** of a symlinked `AGENTS.md` that becomes empty deletes the link, not its target.
- Verified: real Codex (0.163.0) followed the generated block (`codex exec` quoted its codeword).
- **§1** an instruction file whose text holds the zzpersona markers (a project file linked to the
  repo's `AGENTS.md`, which spec 08 allows) is refused at compile: inlining it would nest the block
  in itself.
- **§3 executor** refuses overlay content that holds its own block markers, and refuses to write
  through a symlink whose real target is outside the project (`--check` still reads it).
- **§3 CLI** `write` refuses an overlay without `block` (`overlay-needs-block`): until overlays
  carry an ownership marker, it only merges marked blocks and never replaces a file it does not own.
