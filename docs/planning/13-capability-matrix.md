# 13 — The capability matrix: `donn capabilities` and `docs/capabilities.md`

> Status: design, 2026-10-21. Phase 2, third item (order agreed: agents-md, Codex, capability
> matrix, daemon). Builds on `05-adapter-sdk.md` (capabilities, report, conformance kit), `11`
> and `12`. Replaces the hand-filled table in `03` §Capability matrix. Built as a `gh stack`: layer
> 0 is this spec and its plan.
> 2026-10-23: renamed zzpersona/hatrack → donn (spec 22).

## Intent

Publish exactly what each harness can carry and enforce, from the adapters' own code rather than
from guesses (roadmap Phase 2: "here is exactly what each tool can and cannot enforce"). Readers
are people evaluating donn and policy owners who need to know where enforcement is advisory.
The published matrix cannot drift from the adapters, and it says the same words the loss report
says.

## Decisions (and the alternatives rejected)

| Decision | Rejected | Why |
|---|---|---|
| A command plus a committed doc generated from it, kept current by a test | A doc generated by a script only; a hand-written doc | The command also covers third-party adapters and this machine's mode; a hand-written doc drifts |
| Every field declared; every non-native field carries a note (conformance kit) | Optional notes, "—" when missing | A matrix without reasons is not credible; a missing field silently meant "none" |
| `requiredEntries` takes the report reason from the note | Adapters keep their own reason strings | The matrix and the loss report cannot disagree |
| Item-specific drops stay in compile, flagged by a `caveat` on the field | Encode every per-item rule in the matrix | They depend on the item (a gateway ref, a secret in args), not on the field |

## 1. The SDK contract

- **Every field declared.** `capabilities()` declares every fixed field (`instructions`, `skills`,
  `mcp.servers`, `knowledge`, `secrets`, `permissions.allow|deny|ask`), each `hooks.<event>`, and
  `targets.<own id>`. The conformance kit fails an adapter that leaves one out.
- **Notes.** A field whose support is not `native` must have a `note`; the kit fails one without.
  The note is a reason, written to be read as one ("Codex has no per-launch skill root").
- **Caveats.** A capability entry gains an optional `caveat`: a short note on a field that is
  native in general but where some items can still be dropped or changed (for example
  `mcp.servers` on Codex: "servers whose secret cannot be forwarded by name are dropped; see the
  report").
- **Reasons from notes.** `requiredEntries` returns `{ path, outcome, reason }`, the reason being
  the field's note. Adapters stop writing field-level reasons; their item-specific entries
  (gateway refs, secrets in args or headers, shared or reserved variable names, unknown `targets`
  keys) stay in compile.
- **Detection.** `capabilities(detection?)` is unchanged; Claude Code's degraded modes give the
  fields they lose mode-specific notes ("managed settings block --plugin-dir").
- **Third-party adapters** run the same kit, so one that leaves fields out now fails it. The SDK
  changeset says so (minor at 0.x); spec 05 gets a dated note.

## 2. The command and the doc

**`donn capabilities [--harness <id>] [--detect] [--markdown] [--json]`**

- **Default:** every available harness (first-party plus third-party from config), as a grid:
  rows are fields, columns harnesses, cells `●` native, `◐` approximated, `○` advisory, `✕` none,
  with a `*` on a cell that has a caveat. Notes are numbered under the grid; one note shared by
  several cells is listed once. The grid fits 80 columns.
- **Row collapsing:** `permissions.allow|deny|ask` show as one `permissions` row, and the hook
  events as one `hooks` row, when every harness gives them the same support and note; otherwise
  each shows on its own row.
- **`--harness <id>`:** one harness, one line per field with its support, note and caveat.
  Unknown id: `unknown-harness`, as `compile`.
- **`--detect`:** each adapter's matrix for this machine's detection (Claude Code in `partial`
  mode under blocking managed settings), with the detected version or "not installed" in the
  column header. Without it nothing is probed and each adapter shows its full matrix.
- **`--markdown`:** the published form, a Markdown table with the notes as footnotes.
- **`--json`:** `{ harnesses: [{ id, detected?: { installed, version? }, fields: { <field>:
  { support, note?, caveat? } } }] }`, every field listed, uncollapsed.

**`docs/capabilities.md`** is the `--markdown` output for the first-party adapters without
detection, under a short header: what the symbols mean, approximated ("carried, but weaker or as
guidance") versus advisory ("shown to the model, not enforced"), that the report of each compile
names the exact items, and one line listing harnesses without an adapter yet (Copilot CLI,
Cursor, Gemini CLI, Antigravity). `pnpm docs:capabilities` regenerates it. A CLI test renders it
and compares it byte for byte with the committed file; a stale doc fails with a message naming
`pnpm docs:capabilities`. `.prettierignore` already excludes `docs/`.

`03` §Capability matrix gets a dated note pointing to `docs/capabilities.md`; the README links it.

## 3. Stack and testing

| Layer | Contents |
|---|---|
| 0 `spec` | this spec and its plan |
| 1 `sdk` | `caveat`; `requiredEntries` reasons; conformance checks for declared fields and notes; toys |
| 2 `adapters` | claude-code, agents-md, codex: notes and caveats in `capabilities()`, field-level reason maps removed |
| 3 `cli` | `donn capabilities`: grid, collapsing, footnotes, `--harness`, `--detect`, `--markdown`, `--json` |
| 4 `docs` | `docs/capabilities.md`, `pnpm docs:capabilities`, the staleness test, notes in `03` and `05`, README, changeset, CLAUDE.md |

- **SDK:** each new conformance check fails its own broken toy and passes the good toy;
  `requiredEntries` reasons equal the notes.
- **Adapters:** golden builds regenerated; field notes keep today's reason wording where there is
  one, so the golden diff is small, and every changed line is read.
- **CLI:** the first-party grid within 80 columns; collapsing and its expansion when hook events
  differ; `--harness codex`; `--json` shape; `--detect` with a probe reporting blocking managed
  settings shows Claude Code partial; a third-party adapter appears as a column.
- **Docs:** the staleness test fails on an edited doc and names `pnpm docs:capabilities`.

## Non-goals

Columns for harnesses without an adapter; a docs website; changing what any adapter supports.
