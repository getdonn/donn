# e2e/bin

PATH shims for the Playwright tests (`e2e/fixtures.ts` puts this folder first on the `PATH` of
the daemon and of every `donn` the tests run). They stand in for what the app must never touch
in a test: a browser, a keychain, the network, eve, Vercel and Docker. They are test fakes on
`PATH`, never a seam in production code: the CLI runs them exactly as it would run the real
tools.

| Shim                      | Stands in for                               | Answers                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| ------------------------- | ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `open`, `xdg-open`        | the OS opener                               | records its argument in `$DONN_E2E_OPENED`; opens nothing                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `security`, `secret-tool` | the keychain tools                          | always fail, so a registry token goes to a file                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `pnpm`                    | pnpm and the agent's own eve and Vercel CLI | `install` (an empty `node_modules/eve`); `--package=eve@<v> dlx eve init <dir> --non-interactive` (a minimal agent: `agent/agent.ts` with `defineAgent`, `pnpm-workspace.yaml`); `exec eve build` (`.output/`); `exec eve start --host <h> --port 0` (a real HTTP server on a free port, its `[START] server listening at …` line, alive until signalled); `exec eve add <item>` (below); `exec eve link` (`.vercel/project.json`); `exec eve deploy` (a `*.vercel.app` URL); `exec vercel --version`; `exec vercel env add` (reads the value on stdin and drops it) |
| `npm`                     | npm's registry reads                        | `view eve versions --json` (`["0.83.2"]`), `view vercel version` (`50.1.0`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `docker`                  | Docker                                      | `info` answers; `ps` lists no `eve-sbx-` containers                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `git`                     | `git ls-remote`                             | `ls-remote --tags …` lists `eve@0.83.2`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

`eve add` replays the CLI's recordings (`src/apps/cli/src/test/eve-add/`, eve 0.83.2), by item:

- `channel/github`: the multi-select question `github-events` (exit 2); once answered, completed,
  with the answers it got kept in the agent's `.e2e-answers.json` for the test to check.
- `channel/secret`: a secret question (`kind: "environment"`, variable `E2E_WEBHOOK_SECRET`).
- `channel/linked`: the `eve link` prerequisite.

The UI tests create agents from `eve:blank` (or a path template), so no template tarball is
ever fetched.
